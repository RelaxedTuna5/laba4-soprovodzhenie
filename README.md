## 1. Назначение и функциональные возможности

Программное средство осуществляет прямое взаимодействие с сервером JIRA (по умолчанию общедоступным сервером Apache JIRA: `https://issues.apache.org/jira`) через официальный **REST API v2** и выполняет аналитическую обработку данных с построением следующих отчетов и диаграмм:

1. **Гистограмма времени в открытом состоянии**: отражает продолжительность нахождения задач от момента создания (`created`) до момента закрытия (`resolutiondate`) в днях для закрытых задач.
2. **Диаграммы распределения времени по состояниям задачи**: вычисляет фактическое время нахождения задач в каждом статусе (`Open`, `In Progress`, `Patch Available`, `Resolved`, `Closed` и др.) на основе детальной истории изменений (`expand=changelog`).
3. **График заведенных и закрытых задач в день с накопительным итогом**: строится 4 кривых:
   - Ежедневно создано;
   - Ежедневно закрыто;
   - Накопленный итог созданных;
   - Накопленный итог закрытых.
4. **График задач для пользователей (Топ-30)**: горизонтальная столбчатая диаграмма для 30 наиболее активных пользователей с суммарным числом задач, где пользователь выступает в роли исполнителя (`assignee`) или автора (`reporter`).
5. **Гистограмма затраченного времени на основе залогированного времени (`timespent`)**: отображает фактические трудозатраты (в часах) для задач с заполненным журналом работ.
6. **График задач по степени серьезности**: распределение задач по приоритетам (`Blocker`, `Critical`, `Major`, `Minor`, `Trivial`).

## 2. Структура проекта

```text
Лаба4 Сопровождение/

│   ├── __init__.py             # Инициализация пакета
│   ├── jira_api.py             # Клиент JIRA REST API, кэширование, обработка ошибок

│   ├── utils.py                # Логирование, конфигурация, парсер дат
│   └── main.py                 # Главная точка входа, интерактивное меню и CLI
├── tests/                      # Модульные автоматические тесты
│   ├── __init__.py
│   └── test_tasks.py           # 8 unit-тестов с mock-изоляцией
├── config.ini                  # Конфигурационный файл настроек
├── requirements.txt            # Зависимости Python
├── setup.py                    # Скрипт сборки в дистрибутив (wheel / sdist)
├── run.bat                     # Скрипт запуска для Windows
├── run.sh                      # Скрипт запуска для Linux/macOS
├── README.md                   # Документация по проекту
├── .gitignore                  # Правила исключений Git
├── dist/                       # Собранные пакеты дистрибутива
└── results/                    # Построенные графики и диаграммы (PNG)
```

## 3. Установка и запуск

### Требования:
- Python 3.8+ (протестировано на Python 3.10)
- Установленные библиотеки: `requests`, `matplotlib`, `python-dateutil`

### Быстрый запуск:
```bash
# Под Windows:
run.bat

# Либо напрямую через Python:
python -m jira_analytics.main
```

### Параметры командной строки:
```bash
# Пакетное построение всех 6 отчетов для проекта KAFKA:
python -m jira_analytics.main -p KAFKA --all

# Построение отчетов для проекта HDFS с принудительным обновлением кэша:
python -m jira_analytics.main -p HDFS --all --refresh
```

---

## 4. Сборка дистрибутива

Для сборки программного средства в платформонезависимый wheel-пакет и tar-архив:
```bash
python setup.py sdist bdist_wheel
```
Собранные пакеты сохраняются в каталоге `dist/`.

---

## 5. Запуск тестов

Для запуска всех 8 автоматических модульных тестов:
```bash
python -m unittest tests/test_tasks.py -v
```
Все тесты изолированы с использованием `unittest.mock` и не требуют внешнего сетевого подключения.
